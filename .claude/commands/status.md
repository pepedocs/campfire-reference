---
description: Show a topic's status, cached or fresh
argument-hint: <topic>
---
Show a topic's status from its cache in `status/<topic>.md`. Never read the whole topic file when a cache exists.

$ARGUMENTS must name a topic (match it like `/report` does). If it's empty or unknown, reply with one line: "Usage: /status <topic>" and the topic names. For one entry's history, use `/history <name>`.

**Cache format:**
```markdown
# Risks status

Generated by campfire `/status`. Don't edit by hand.

Open: 1 · Resolved: 1

- **Risk-2** (Bob) · updated 2026-08-09: Launch-day traffic may exceed the current plan's limits. · Validate: Hosting plan limits page.
- **Risk-1** (Alice, Charlie) · updated 2026-08-07: Resolved. Provider signed off on checkout. · Validate: Sign-off thread.
```
One line per entry: a one-sentence summary and a short form of its validation line, open entries first. Never drop the validation. Store dates, not staleness markers.

**Steps:**

1. **Cache exists:** `git log -1 --format='%h %ci' -- status/<topic>.md` gives its commit and time. Count changes since with `git rev-list --count <commit>..HEAD -- topics/<topic>.md`. Show the cache with staleness markers and "Cached <time> · <N> changes since." If N is 0, say it's current and stop. Otherwise ask: "use this, or get a fresh status?" and stop.
2. **Fresh:** read only the changes since the cache:
   `git log -p -U0 --format='%h %an %ad' --date=short <commit>..HEAD -- topics/<topic>.md`
   Apply them to the cache: add new entries, rewrite changed ones, drop removed ones, update the counts. Each changed entry's date is its commit's date.
3. **No cache:** the only time to read the whole topic file. Build the cache, taking dates from `git blame --date=short`.
4. After 2 or 3: commit `[campfire-status] update status for <topic>`, show the cache, then ask: "push to <branch>?"

**Staleness markers** (added when showing, from the cached dates and today's date): 5+ days since the last update is "⏳ almost stale", 7+ days is "⚠️ stale". Resolved entries are never stale.

**Conflicts:** if a pull or push conflicts on a cache file, resolve the topic file first, then rebuild the cache from it.

User input: $ARGUMENTS
